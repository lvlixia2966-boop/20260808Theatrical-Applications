## 1. 【P0】首访浏览器语言自动匹配

**现状**：`index.html` 的 `restoreLanguage()` 仅在 localStorage 有 `app_lang` 时恢复，否则默认中文。外国游客首次打开全中文页面，5 秒内可能流失。

**整改内容**：无本地记忆时，取 `navigator.language` 前 2 位匹配 7 种界面语言（zh/en/ja/ko/fr/de/es）；命中即静默切换；不命中保持中文。用户手动选过语言后，本地记忆永远优先。

**修改路径**：

```
frontend/index.html  restoreLanguage()
  saved = localStorage.getItem('app_lang')
  if saved → 恢复 saved（现状不变）
  else →
    nav = (navigator.language || 'zh').slice(0,2)
    if nav in {en,ja,ko,fr,de,es} → setLanguage(nav, names[nav], null, silent=true)
```

**错误预防**：
- 必须传 `silent=true`：自动切换不弹 toast，避免游客打开即被中文提示打断
- `setLanguage` 切换会触发 `app:langchange` → 剧场介绍自动跟随重载，无需额外处理；但需确认介绍请求时序在模块初始化之后（theatre-intro.js 初始 loadIntro 也读同一 localStorage，**首访时两者都无记录**：restoreLanguage 先执行并写入 localStorage，theatre-intro.js 后加载即读到新值——脚本顺序 `creator-hub.js → theatre-intro.js` 且 setLanguage 定义于内联脚本，天然满足；若日后调整脚本顺序，需改为统一事件驱动）
- 语言名映射复用现有 `names` 表，新增语言只改一处
- 验收：清 localStorage + 浏览器语言设为 en → 打开首页即英文界面+英文介绍+英文徽章

## 2. 【P0】剧场介绍补实用信息

**现状**：介绍文案（8 语言预置）只有艺术背景 + 静音/闪光灯礼仪，缺游客最需要的：**演出时长、中场休息、取票方式、交通指引**。

**整改内容**：在 `INTRO_ZH / EN / JA / KO / ES / FR / DE / RU` 各版本句末统一追加一段实用信息（每种语言各自手写，不走机翻）：

> 中文版追加：「本场演出约 90 分钟，中场休息 15 分钟。请提前 30 分钟凭购票二维码在售票厅取票。剧场位于 XX 路 XX 号，地铁 X 号线 XX 站 B 出口步行约 5 分钟。迟到观众请听从工作人员指引于幕间入场。」

英文版对应翻译（如 "The performance lasts about 90 minutes with a 15-minute intermission..."）。

**修改路径**：
```
backend/app/services/intro_service.py
  8 个 INTRO_XX 常量各追加「实用信息段」
  （位置信息暂用占位文案，上线前由剧院方确认替换）
```

**错误预防**：
- **禁止**把追加段交给 translation_service 动态翻译——地址、地铁线路名机翻必错（回看历史：日文版曾把「劇場」译成「病院」）；8 语言全部手写
- 追加后文案变长，TTS 合成耗时增加：前端 `theatre-intro.js` 已有「语音合成中…」过渡态，无需改；但需回归验证 Edge TTS 长文本不超时（当前英文版约 41 秒音频，追加后预计 <60 秒，安全）
- 占位地址用醒目标记（如「XX路」），并在常量上方注释「上线前替换」，防止占位信息直接上线
- 验收：8 种语言 `GET /api/live/intro` 均含新段落；中/英/日三语 TTS 试听完整

## 3. 【P1】经典唱段与术语预置韵译库

**现状**：字幕翻译走 Google → MyMemory 链式机翻。机译两大风险：①术语错译（「变脸」可能译成 face change surgery 语境；「帮腔」无人知晓）；②唱词失去诗意（「别时容易见时难」→ 生硬直译）。

**整改内容**：新建**术语+唱段预置译文库**。字幕翻译前先查库：整句命中唱段库→直接用预置韵译；句中含术语→翻译后将术语译文规范化替换。

**修改路径**（高内聚：译文库独立成模块，live_hub 只在管线中插一步查询）：
```
backend/app/services/glossary_service.py   新建
  - TERMS: dict[str, dict[lang, str]]      术语库（变脸/吐火/帮腔/高腔/折子戏/水袖...）
  - LYRICS: dict[str, dict[lang, str]]     经典唱段整句韵译（白蛇传/秋江/滚灯代表唱词）
  - lookup_term(text, lang) / lookup_lyric(text, lang) / apply_terms(text, lang, translated)

backend/app/services/live_hub.py           管线插入
  翻译后处理：translated = glossary.apply_terms(orig, lang, translated)
  翻译前短路：hit = glossary.lookup_lyric(orig, lang) → hit 直接用
```

**错误预防**：
- 术语库**首期只收 20~30 个高频词**，由懂行人核对后入库；宁缺毋滥，错译文比机翻更伤信任
- `apply_terms` 用词边界匹配（避免「变脸」子串误伤其他词），中文按整词、英文按 `\\b` 正则
- 唱段库 key 存**规范化的中文原句**（去标点、去空白）再匹配，ASR 识别结果带标点/多空格也能命中
- 查库失败/未命中必须**静默走原机翻流程**，glossary 任何异常不得中断字幕管线（try/except 包裹，日志降级 warning）
- 验收：模拟字幕「别时容易见时难，流水落花春去也」→ 英文输出预置韵译而非机翻

## 4. 【P1】WS 协议扩展看点提示（highlight）

**现状**：协议仅 caption / listeners / session_end / ping。技巧型节目（吐火/滚灯/变脸）的外国观众不知道「看什么」，只觉得有人在钻板凳。

**整改内容**：
- 协议新增 `MSG_HIGHLIGHT = "highlight"` 消息：`{"type":"highlight","text":"看点","translations":{...},"ts":秒}`
- 来源两种：①管理后台场次设置时预挂「看点脚本」（按时间点/手动触发）；②讲解员话术被 ASR 识别后，命中 glossary 术语自动升级为看点卡片（如识别到「吐火」→ 推送该绝技的英文看点）
- 前端字幕流中看点以**强调样式卡片**插入（区别普通字幕），几秒后自动收起

**修改路径**：
```
backend/app/schemas/live.py        +MSG_HIGHLIGHT 常量与 docstring 协议说明
backend/app/services/live_hub.py   +highlight() 广播方法；ASR 命中术语时调用
backend/app/api/live.py            （不动——WS 通道复用现有连接）
frontend/assets/js/live-listen.js  消息分支 + highlight 卡片渲染（限高样式，自动消失）
frontend/live-listen.html          highlight 卡片样式
```

**错误预防**：
- **协议向后兼容**：旧客户端收到未知 type 已默认忽略（确认 live-listen.js 现有 default 分支不报错）；新常量只增不改
- 术语触发看点需**节流**（同一术语 60 秒内不重复推送），避免讲解员反复提到「变脸」刷屏
- highlight 不入历史字幕缓存（`history` 只存 caption）：中途进场的观众补发历史时不需要过期看点
- 前端卡片 `pointer-events:none` + 固定 max 条数（同屏最多 1 条），不遮挡字幕主区
- 验收：模拟推送 highlight → 收听席出现强调卡片且 8 秒自动收起；旧消息分支回归无报错

## 5. 【P1】节目单多语言一句话简介

**现状**：首页节目单为内嵌静态演示数据，节目名有 i18n 但**无内容简介**；节目模型（Program）也无简介字段。外国观众看不懂「皮金滚灯」是什么。

**整改内容**：
- `Program` 模型加 `intro_zh / intro_en` 字段（一期中英双语即可，其余语言走机翻+术语库）
- 每个节目一句话简介：「滚灯：演员头顶燃灯钻板凳翻滚，是川剧独门喜剧绝技」
- 首页时间轴卡片展示当前语言简介；API 公开查询返回简介并按请求语言回退（en 缺失时回 zh）

**修改路径**：
```
backend/app/models/program.py      +intro_zh/intro_en 列（nullable）
backend/app/schemas/program.py     出参模型加字段
backend/app/api/programs.py        列表返回简介；?lang= 参数决定回退顺序
backend/seed.py                    演示数据补简介
frontend/index.html                节目卡片渲染简介（i18n 当前语言选择 zh/en）
admin/index.html                   节目编辑表单加两个简介输入框
```

**错误预防**：
- DB 加列必须 **nullable + 无默认值**，避免存量数据迁移失败；SQLite/MySQL 双后端都要跑一遍启动建表验证
- 简介回退链固定：请求语言 → en → zh → 空字符串（前端空则隐藏该行，不显示 null 字样）
- `?lang=` 参数做白名单校验（复用 core/languages.is_supported），防脏参数打穿查询
- 验收：中/英界面节目单均显示对应简介；旧数据（无简介）不报错不显示空框

## 6. 【P2】文创面具文化典故语音

**现状**：文创商品为静态卡片（图+名+价），无文化讲解。游客在礼品店不认识关羽、不知道颜色含义，转化与客单受限。

**整改内容**：文创卡片加「听典故」小按钮：点击调用现有 `/api/tts/synthesize` 播放该商品的典故文案（如「红脸关羽：红色象征忠义英勇，关羽是三国名将…」）。文案中英预置于前端商品数据（复用 glossary 思路，防止机翻错典故）。

**修改路径**：
```
frontend/index.html            文创卡片 + 🔊 典故按钮；商品数据对象 + intro_zh/intro_en 字段
frontend/assets/js/            新增 story-audio 小模块（或并入 creator-hub.js，IIFE 封装：
                               播放互斥——同时只播一个，切换商品先停旧音频）
```

**错误预防**：
- **播放互斥**：多个典故按钮同时点击必须只播最后一个（参考 theatre-intro.js 的 stopIntro 模式）
- TTS 长文本（>200 字）注意 Edge 合成耗时，按钮加「合成中…」禁用态防重复点击
- 页面切换（文创子视图切换）时停止播放，避免「看不见的卡片还在响」
- 验收：连点三个面具典故按钮 → 只有一个在播；切走子视图即静音

## 7. 【P2】演出结束旅拍引导

**现状**：AI 旅拍入口藏在 首页→文创→AI旅拍 二级子视图；场次收播（session_end）后观众直接看到结束提示，没有转化动作。游客「想留下可分享记忆」的时机恰好在此。

**整改内容**：收听席收到 `session_end` 时，结束卡片下方展示「留住今晚：AI 川剧旅拍 →」按钮，跳转首页文创 AI 旅拍子视图（带锚点/参数直达，不再两层点击）。

**修改路径**：
```
frontend/assets/js/live-listen.js   session_end 分支 + 引导卡片
frontend/index.html                 支持 ?view=wenchuang&sub=ai-photoshoot URL 直达子视图
                                    （初始化时解析参数调用既有 switchWenchuangSubView）
```

**错误预防**：
- 直达参数必须与现有子视图 id 白名单校验，非法值静默忽略走默认视图（防 URL 注入任意 DOM id 操作）
- 引导卡片出现在 `session_end` 之后、WebSocket 已关闭场景，纯静态渲染不依赖网络
- 跳转携带语言（localStorage 天然共享，无需传参），落地页语言一致
- 验收：收播后出现引导；点击直达 AI 旅拍子视图且语言保持

## 8. 实施顺序与回归清单

**建议批次**（每批独立可验收、可上线）：

```
批次一（P0，立即可做）：#1 语言自动匹配 + #2 介绍补信息
批次二（P1，观演质量）：#3 术语韵译库 → #4 看点提示（依赖 #3 的术语触发）
批次三（P1 收尾）：    #5 节目单简介（含 DB 迁移，单独回归）
批次四（P2，增值）：    #6 典故语音 + #7 旅拍引导
```

**每批通用回归项**：
- [ ] 清 localStorage 首访：浏览器语言 en/ja 各验一次（界面、介绍、徽章三处同步）
- [ ] 手动切语言 → 刷新 → 记忆恢复正确
- [ ] 直播链路冒烟：mock 采集 → ASR → 字幕 → 收听席显示；WS 断线重连
- [ ] TTS 冒烟：中/英/日各合成一段（含 #2 追加后的长文案）
- [ ] 旧浏览器/console 无 JS 报错；管理后台对应模块增删改查正常

**全局风险提示**：
- 所有新文案入库**一律手写预置**，机翻仅兜未覆盖语言（历史教训：MyMemory 曾把「劇場」译作「病院」）
- 所有新 WS 消息类型/URL 参数遵循「只增不改」，保证旧客户端与新服务端任意组合不崩
- DB 变更只加 nullable 列，不动存量列语义
