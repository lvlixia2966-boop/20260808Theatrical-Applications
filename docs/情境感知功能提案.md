# 情境感知功能提案 ·「此情此刻此景」

> 版本 v1.0 · 2026-09-10
> 依据：三方 Agent 研究（情境感知手法 / 川剧观演情绪节拍 / 工程信号盘点）
> 关联：[建设意见与实施路线图](./建设意见与实施路线图.md) 第 1.5 批 · [功能树文档](./功能树文档.md) 1.3 收听视图

## 1. 理念

把应用从「游客找功能」的工具，升级为「知道游客此刻在哪、台上演到哪、什么状态」的**随身陪看**。

| 维度 | 含义 | 信号来源（全部现有架构） |
|---|---|---|
| **此景** | 所在界面 + 台上正演到什么 | 视图状态、实时字幕、绝技关键词命中帧 |
| **此刻** | 旅程阶段 | 场次状态机、start_at/duration 倒计时、字幕静默时长 |
| **此情** | 个人状态 | 首访/回访、护照进度、耳机连接与电量、语言、叫好参与 |

**工程结论**：七个候选功能中五个为纯前端 S 级——信号已全部存在于 LiveSession 字段、字幕流时间戳、高亮帧与 localStorage，唯一缺口是 Web Push（L）。

## 2. 情绪节拍表（导演视角，90 分钟场）

| 时间轴 | 阶段 | 情绪 | 游客典型疑问 | 干预动作 |
|---|---|---|---|---|
| -30~0 分 | 入场候场 | 期待、爱拍照 | 演什么？有字幕吗？ | 倒计时横幅 + 节目预习 |
| 0~5 分 | 开场锣鼓 | 热身 | 这乐器是什么？ | （零打扰，仅字幕） |
| 5~25 分 | 折子戏一 | 沉浸→困惑 | 演的什么故事？ | 随曲目 30 字双语剧情卡 |
| 25~45 分 | 折子戏二 | 兴奋 | 头顶油灯怎么不掉？ | 绝技冷知识卡（高亮通道） |
| 45~60 分 | 折子戏三 | 疲劳渐显 | 还有久？有中场吗？ | 进度细条 |
| 60~75 分 | 中场休息 | 疲劳/无聊（刷手机高峰） | 厕所？下半场？ | 中场模式卡：竞答/购物点/换电提醒 |
| 75~88 分 | 压轴绝技 | 兴奋峰值 | 怎么变的？ | 压轴预警卡 + 叫好共感 |
| 88~93 分 | 谢幕 | 回味不舍 | 能合影吗？ | （零打扰） |
| 93 分后 | 散场 | 纪念欲强 | 纪念品？明晚呢？ | 收播卡（记忆卡/旅拍/明晚） |

**红线**：演出中零打扰——仅 30 字内卡片；长内容只出现在候场与中场。

## 3. 已实现 ✅（2026-09-10，context-engine.js）

情境引擎 = 阶段判定器（~60 行）+ 情境卡调度器（~60 行）+ 自包含样式，事件驱动、零轮询增量：

| 功能 | 触发信号 | 呈现 | 状态 |
|---|---|---|---|
| 候场倒计时横幅 | `/api/live/shows/next`（新增接口）90 分钟窗口 | 大厅金框横幅：距《场次》MM:SS 走秒 + 预习提示；到点变「进入收听」按钮（触发列表刷新） | ✅ |
| 本场进度细条 | app:live:joined 携带场次时间字段 | 字幕卡顶部红金渐变细条，随 elapsed/duration 走 | ✅ |
| 中场模式卡 | 字幕静默 >4 分钟且已播 >10 分钟 | 「🍵 中场休息」+ 竞答/购物点按钮 + 低电量换电提示；字幕恢复自动撤卡 | ✅ |
| 压轴预警卡 | 距收播 ≤8 分钟 | 「🎭 压轴将至 · 变脸吐火，坐稳了」8 秒自净，每场一次 | ✅ |
| 调度纪律 | — | 同时最多 1 张、每类每场 1 次、reduced-motion 降级、?debug 暴露 force 钩子 | ✅ |

验收：222 生产环境四阶段实测通过（倒计时走秒 56:16 → 进度条 0.5%→22% → 中场卡 → 压轴卡 → 收播）。

## 5. 设计红线（长期有效）

1. 演出进行中零打扰：仅 30 字内卡片，禁止长文与弹窗
2. 同时最多 1 张情境卡，每类每场最多触发一次
3. 情境卡必须可一键关闭，且尊重 prefers-reduced-motion
4. 所有文案 zh/en 双语，跟随 app:langchange
