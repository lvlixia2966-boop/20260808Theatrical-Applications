# 川蜀大剧院语音导览系统 · 项目架构文档

> 巴蜀语音导览系统：耳机管理 / 节目上下架 / 文本语音预约 / AI 旅拍 / 场次直播多语言同传 / 文创商城支付
> 版本 v1.3.0 · 后端 FastAPI · 前端原生 HTML/JS · 数据库 MySQL / SQLite

---

## 1. 项目概览

面向川剧院演出场景的多语言语音服务系统，由四部分组成：

| 端 | 说明 |
|---|---|
| `frontend/` | 观众端：首页单页四视图（观剧 / 文创 / 收听 / 个人中心）、语音导览扫码页 |
| `admin/` | 管理后台：节目 / 场次直播 / 预约 / 耳机 / 音色 / 语音设置 |
| `backend/` | FastAPI 后端：REST API + WebSocket + 场次调度器 + 多引擎 AI 服务 + 支付 |
| `deploy/` | 部署辅助：nginx / systemd / 启动脚本 |

**技术栈**：Python 3.11 + FastAPI + SQLAlchemy + Pydantic Settings；前端纯静态（Tailwind CDN + 原生 JS 模块）；TTS/ASR/翻译均为多引擎适配（本地引擎 + 在线服务，链式回退）。

## 3. 后端架构（backend/app）

### 3.1 分层设计

```
main.py                 应用入口：中间件 / 路由装配 / lifespan(建表+启动调度器) / 静态托管
├── api/                路由层：只做协议装配与参数校验，业务委托 service
├── services/           业务层：核心业务编排（直播管线、调度、TTS/ASR/翻译）
├── core/               基础层：纯数据/工具（语言表、音色表、安全、蓝牙校验）
├── models/             ORM 模型：SQLAlchemy 表结构
├── schemas/            Pydantic 模式：请求/响应契约（含 WS 消息协议）
├── config.py           集中配置：环境变量 → Settings 单例
└── database.py         引擎与会话：统一 Session 依赖
```

依赖方向自上而下单向：`api → services → core/models`，层内互不引用实现细节。

### 3.3 服务层（services/）—— 核心

| 模块 | 职责 | 关键设计 |
|---|---|---|
| `doubao/` | 豆包云能力统一客户端包（火山方舟 + openspeech 语音） | `ark_client`（LLM/翻译/视觉/向量/生图，OpenAI 兼容 REST）、`asr_stream`/`asr_oneshot`（大模型流式 ASR）、`tts_stream`（单向流式 TTS）、`protocol`（语音二进制协议）；凭据未配置时各调用方自动走降级路径 |
| `live_hub.py` | 直播枢纽：运行时会话注册表 + 字幕生产线编排 + 原声/字幕广播 | 管线：PCM 块 → 原声广播 → ASR 断句 → 多语言翻译 → caption 广播；历史字幕缓存（中途加入补发） |
| `rtc_gateway.py` | WebRTC 实时翻译网关（报价单 #15） | 信令处理、媒体轨道收发、ASR 喂入、字幕广播、peer 生命周期统一在此；与 live 域零 import 耦合（仅共享引擎抽象）；aiortc 实现，Opus 帧 → PCM16k → 引擎喂入 |
| `rtc_pipeline.py` | RTC 双向翻译链路编排 | 链路 A/B（讲解员→游客 / 游客→讲解员）的「翻译 → 记录 → 语音」编排收敛在此 |
| `translate_pipeline.py` | 翻译优先级策略（报价单 #16 术语表环节） | 术语韵译整句优先 → 豆包 LLM 翻译 → 回退原文不阻断 |
| `agent_service.py` | Agent 伴游问答（报价单 #12-14） | RAG 召回 → 提示词组装 → 豆包 LLM → 引用校验 → 安全降级，全流程在此 |
| `retrieval_service.py` | 知识库混合检索 | BM25 + 向量余弦双路召回、RRF 融合、抽检/节点加权；索引自动重建（数据变更 invalidate）；纯 Python 实现低内存占用 |
| `usage_meter.py` | 豆包用量计量（报价单 #16/#21） | 计量口径（kind/unit/折算）与预算告警阈值收敛在此；ASR 秒 / 翻译与 TTS 字符 / LLM token 落 UsageLog |
| `show_scheduler.py` | 场次调度器：预设场次到点自动开播/收播，无人值守 | 状态机 scheduled→live→ended；每 tick 巡检；服务重启自动恢复会话续采 |

| `asr_service.py` | 语音识别引擎适配层 | 抽象 `AsrEngine` + 工厂：豆包大模型流式 ASR（云端 openspeech）/ Mock 演示引擎；断句策略收敛在基类模板方法 |

## 4. 核心数据流

### 4.1 场次直播同传管线（无人值守）

```
管理后台设置场次(scheduled)
        │  到点（show_scheduler 巡检）
        ▼
   自动开播：live_hub 创建 LiveSession + CaptureWorker 启动采集
        │
        ▼
剧场调音台 → 声卡 Line-In → PCM16/16k/mono 块（200ms/块）
        │
        ├──────────────► 原声广播（audio=1 的观众，WS 二进制帧）
        ▼
   ASR 引擎流式识别（断句）→ 完整中文句
        ▼
   translation_service → 多目标语言并行翻译
        ▼
   caption(原文+译文+序号) → 历史缓存 → WS 文本帧广播全部观众
        │
        ▼  到时 / 手动收播
   session_end → 销毁会话与采集任务
```

观众端（首页收听视图 #view-livelisten）：进入即补发近期历史字幕；原声经 AudioContext 排队播放；可选译文 TTS 播报。

### 4.2 TTS 合成引擎链

```
请求(text, lang)
  → 豆包云 TTS（openspeech：整段 HTTP 返回 MP3；RTC 场景走 v3 单向流式 PCM）
  → 未配凭据 → mock 占位（演示模式）
音色解析：显式指定 > DOUBAO_TTS_VOICE_OVERRIDES 环境覆盖 > core/voices 语言注册表 > 中文默认
```

### 4.3 入场剧场介绍（首页集成）

```
首页语言下拉切换 → localStorage(app_lang) + app:langchange 事件
   → theatre-intro.js 跟随事件 → GET /api/live/intro?lang=xx
   → intro_service（预置16语言 / 动态翻译 / 医院词黑名单 / 英文兜底）
   → 前端 GET /api/tts/synthesize 按语言合成播放
刷新首页 → restoreLanguage 从 localStorage 恢复上次语言
```

### 4.4 耳机准入流程（ble-guard.js）

```
扫码进入服务页 → 全屏准入页（仅语言选择 + 连接专用蓝牙耳机）
        │  Web Bluetooth requestDevice(namePrefix='CHUAN')
        │  或「暂不连接，直接进入」跳过（window.BLE_GATE_CONFIG.skipEnabled 控制，
        │    sessionStorage 记忆、不派发 ble:connected；生产环境可置 false 关闭）
        ▼
连接成功 → GATT 读电量(0x180F/0x2A19) → 60s 轮询 → 解锁正式页面
        │
        ├─ 低电量(<20%) → 提示充电后继续使用
        └─ 断连 → 兜底暂停页面全部 <audio> + 派发 ble:disconnected
                （各音频模块自行监听清理）→ 回退准入页 → 3s 间隔自动重连
?demo=1 开发旁路；getDevices() 静默重连曾配对设备
```

耳机为付费凭证：**租用在剧院门口柜台线下完成，线上不收费**；服务页仅校验连接。

### 4.5 文创商城支付链路

```
文创商城加购（cart.js 接管全部加购按钮，localStorage 持久化）
        │  浮动球显隐：文创视图常显，其他视图仅有商品时显示
        ▼
购物车抽屉结算 → checkout.js → POST /api/payments/orders（商品快照）
        │  GET /api/payments/channels 决定渠道（未配 PayPal 凭证自动降级 mock）
        ▼
选渠道（微信/支付宝/PayPal）→ 沙盒收银台 iframe（mock-cashier.html）
        │  或 PayPal JS SDK 沙盒按钮
        ▼
前端 2s 轮询订单状态 → paid → 清空购物车 + 派发 app:order:paid
```

切换真实支付：`backend/.env` 配置 `PAYPAL_CLIENT_ID/PAYPAL_SECRET` 即启用 PayPal 沙盒；微信/支付宝商户号就绪后替换 mock_gateway。

### 4.6 WebRTC 双端实时翻译（报价单 #15）

```
讲解员端(admin) 创建会话 → POST /api/rtc/sessions → 令牌 + 二维码
        │  游客扫码进入 frontend/index.html?view=rtc&code=X（rtc-session.js）
        ▼
双端各自 RTCPeerConnection 协商（HTTP 轮询信令，局域网 host 候选直连）
        │
        ▼
远端音频轨（Opus）→ aiortc 解码 → PCM16k → 豆包流式 ASR（按说话方分链路）
        │
        ├─ 链路 A（讲解员→游客）：中文句 → 翻译（术语韵译优先）→ 字幕广播 + 游客语 TTS
        └─ 链路 B（游客→讲解员）：外语句 → 中译 → 字幕广播
        ▼
字幕持久化 RtcCaption + 断线 60s 内同令牌重连复用会话
```

并发上限 `RTC_MAX_SESSIONS`（默认 8）；跨网段部署时配置 `RTC_STUN_URLS`。

### 4.7 Agent 伴游 + 知识库 RAG（报价单 #10-14）

```
游客提问（文本/语音）
        │  文本：POST /api/agent/chat
        │  语音：POST /api/agent/voice（MediaRecorder 上传 → av 解码 →
        │        豆包单发 ASR 转写 → 复用 chat 管线 → 返回「识别文本 + 回答」）
        ▼
agent_service：retrieval_service 混合召回（BM25 + 向量余弦 → RRF 融合）
        │  → 提示词组装（召回片段 + 多轮上下文）
        ▼
豆包 LLM（流式）→ 引用校验（答案须可溯源到知识单元）→ 回答
        │  LLM 不可用/超时 → 安全降级话术（AgentMessage.degraded 标记）
        ▼
回答多语言 → 豆包流式 TTS 播报；全过程用量落 UsageLog
```

知识库运营链路：admin 知识管理页维护 节点 → 知识单元 → 译文 / 实体图谱 / 验收问集；
数据变更后 `retrieval_service.invalidate()` 自动重建索引；「生成向量」按钮批量调方舟 embedding 落 KnowledgeVector。

### 7.3 本地离线语音引擎（沙盒 · agent_ 伴生项目）

- CosyVoice3（Fun-CosyVoice3-0.5B）常驻合成服务 `:9881`（强制 GPU，禁止 CPU 回退），供数字人/伴游项目做音色克隆合成；川剧入场语音两版（迎宾热闹 13.9s / 茶馆开腔 13.1s，24kHz WAV）已预烘焙交付。
- **指令归一化实证约束**（`cosy_server.py` `_norm_instruction`）：Fun-CosyVoice3-0.5B 的 instruct 指令必须带英文系统前缀 `You are a helpful assistant. `、长度 ≤24 字、并以 `<|endofprompt|>` 结尾——缺前缀或指令超长时抑制失效，指令会被原样朗读进音频。服务端统一归一化兜底，经 FireRedASR 转写复测零泄漏，并已在服务冷启动后复现验证。
- 本引擎独立于 chuan 主服务部署，不影响「AI 全走豆包云」的线上架构；如需入场语音接入开场流程，直接使用预烘焙音频即可。

**踩坑记录（2026-09 入场语音合成实测）**

模型行为坑：
- 指令被念出：缺英文系统前缀或指令超长（>24 字）都会使 `<|endofprompt|>` 抑制失效，指令被原样朗读；实证 ≤16 字最稳。修复为 `_norm_instruction` 统一「剥旧前缀 → 截断 ≤24 字 → 补前缀+终止符」兜底；空指令直接传 `<|endofprompt|>` 本身。
- 服务重启后配置未生效复现：曾因同文件多处并行编辑相互覆盖，归一化函数丢失 `<|endofprompt|>` 拼接（断言失败）。同文件修改必须顺序执行，改完在重启后验证关键函数。

环境与启动坑：
- 嵌入版 Python（`.tools/cosyvoice/python`）缺 numba，无法启动；服务必须用 venv 的 `pythonw.exe`（`.tools/cosyvoice/venv/Scripts/`）启动 `run_cosy.py`。
- numba 缓存探测（TemporaryFile）在本机被杀软/过滤驱动卡死：`run_cosy.py` 启动时 monkeypatch `ensure_cache_path` 绕过。
- onnxruntime 找不到 `cublasLt64_12.dll` 会静默回退 CPU：启动前须将 CUDA v12.4 的 bin 目录加入 PATH。
- pythonw（无控制台）下 `sys.stdout/stderr` 为 None，print/logging 直接崩：启动包装器先把日志重定向到文件。
- wetext 中文前端默认走 modelscope 在线下载（repo-files API 会 403）：须在 AutoModel 初始化前 patch `snapshot_download` 指向本地 wetext 缓存。

资源与验证坑：
- 合成与 ASR 不宜同卡同跑，显存吃紧时转写先挂：ASR 验证用独立 `asr-env` 按需启停。
- 验证「指令零泄漏」用 FireRedASR 转写合成结果；ASR 存在同音字误差（剧场→菊草、变脸→别脸、吐火→土火），断言应针对指令关键词而非逐字比对。

## 8. 高内聚低耦合设计原则

全项目贯穿统一的设计约定：

1. **按功能域划分模块**：直播（live*）、语音（tts*）、导览（program/reservation）、设备（earphone）各自成域，域内闭环。
2. **抽象 + 工厂 + 链式回退**：ASR / TTS / 采集 / 翻译四类外部能力均为「抽象接口 + 多实现 + 自动回退」，业务层只依赖接口（如 `AsrEngine`、`AudioCapture`、`TranslationProvider`）。
3. **路由薄、服务厚**：api 层只做协议装配与生命周期管理，业务编排全部在 services。
4. **运行时与持久化分离**：`LiveShow`（DB 排期）与 `LiveSession`（内存运行时）分离，调度器负责两者状态同步与服务重启恢复。
5. **纯数据收敛 core**：语言表、音色表、校验逻辑等纯数据/工具统一在 core，被多方复用而不反向依赖。
6. **前端事件解耦**：语言切换等跨模块状态用 CustomEvent 广播，模块间零直接引用。
7. **每模块头部 docstring 声明其高内聚点与低耦合边界**，作为后续维护的契约。
