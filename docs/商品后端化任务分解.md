# 商品后端化 · 任务分解

版本：v1.0（2026-09-29）　状态：待评审，未写代码
范围：中国川剧文创旗舰店（`#subview-cultural-mall`）的 8 件商城商品；IP 资产库、AI 旅拍等展示型卡片**不在本期范围**。

## 一、现状

| 项 | 现状 | 问题 |
|---|---|---|
| 商品数据 | 8 张静态卡片硬编码在 `frontend/index.html`（分类/名称/描述/价格/图片/角标） | 改价需改代码并部署 |
| 商品 ID | `cart.js` 用**图片文件名**当 id（`productFromCard` 解析 DOM 文本） | 脆弱，依赖 DOM 结构 |
| 下单 | `POST /api/payments/orders` 接收前端快照 `{id,name,price_cents,qty}`，**后端不校验价格与存在性** | 价格可被篡改 |
| 管理 | 无商品管理，无上下架/库存概念 | 运营不可自助 |
| 图片 | 静态文件 `./assets/products/*.jpg` | 与商品数据分离 |

## 二、商品表结构（`products`）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| sku | VARCHAR(32) UNIQUE | 商品编码（如 SHOP-001），替代"图片文件名 id" |
| name | VARCHAR(128) NOT NULL | 中文名 |
| name_en | VARCHAR(128) | 英文名（可空；其余语言回退中文，与现状一致） |
| description | TEXT | 中文描述 |
| description_en | TEXT | 英文描述（可空） |
| category | VARCHAR(16) | embroidery / accessory / lacquer / bamboo |
| price_cents | INTEGER NOT NULL | 售价（分），下单校验基准 |
| orig_price_cents | INTEGER | 划线原价（可空） |
| image_url | VARCHAR(255) | 首期沿用 `./assets/products/*.jpg`；新上传落 `uploads/products/` |
| badge | VARCHAR(32) | 角标（如"非遗工艺"，可空） |
| stock | INTEGER | 库存（NULL=不限，演示期建议 NULL） |
| sort | INTEGER | 排序权重，小者在前 |
| status | INTEGER | 1 上架 / 0 下架（下架即软删） |
| created_at / updated_at | DATETIME | 时间戳 |

## 三、API 端点清单

**公开（游客端，无鉴权）**

| 端点 | 说明 |
|---|---|
| `GET /api/shop/products` | 上架商品列表（status=1，按 sort），游客端渲染数据源 |

**管理端（Bearer JWT；写操作限 `super`/`ops`，复用 `require_role`）**

| 端点 | 说明 |
|---|---|
| `GET /api/admin/products` | 全量列表（含下架） |
| `POST /api/admin/products` | 新建 |
| `PUT /api/admin/products/{id}` | 编辑（含价格/上下架/排序） |
| `POST /api/admin/products/{id}/image` | 上传图片（multipart，落盘 `uploads/products/`，返回 url） |
| `DELETE /api/admin/products/{id}` | 下架（status=0，不做物理删除） |

**下单校验（改造既有端点）**

| 端点 | 改动 |
|---|---|
| `POST /api/payments/orders` | items 逐条校验：sku 存在、status=1、`price_cents` 与库内一致；不符返回 400（快照仍按校验后数据落库） |

## 四、前端改造点

1. **游客端商城渲染**（`frontend/index.html`）：8 张静态卡 → 空容器 + JS `fetch /api/shop/products` 渲染；分类筛选改为按数据 `category` 过滤；名称/描述按 `app_lang` 取 zh/en（无 en 回退中文）；加载失败显示"商品暂时无法加载"+重试按钮（不回退静态卡，避免双数据源）
2. **购物车**（`frontend/assets/js/cart.js`）：`productFromCard` 改读卡片 `data-id/data-name/data-price-cents`（渲染时写入），不再解析 DOM 文本与图片路径
3. **管理台**（`admin/index.html`）：侧栏新增"商品管理"（`data-nav="products"`，仿节目管理页）；列表 + 新建/编辑表单 + 上/下架 + 排序 + 图片上传；`api()` 通用请求与角色导航机制照旧

## 五、任务分解与验收标准

| # | 任务 | 交付物 | 验收标准 |
|---|---|---|---|
| T1 | 模型与建表 | `models/product.py` + init_db 建表 + seed 写入现有 8 商品（sku/价格/图片沿用现状） | 初始化后表存在；`GET` 可查得 8 条且字段与现静态卡一致 |
| T2 | 公开读 API | `GET /api/shop/products` | 返回仅上架商品、按 sort 排序；空库返回空数组不报错 |
| T3 | 管理 CRUD API | 上表 5 个 admin 端点 | 无 token 401；无权限角色 403；增改查回读一致；图片上传落盘且 URL 可访问 |
| T4 | 下单防篡改校验 | payments/orders 校验逻辑 | 改价/下架/不存在 sku 的 items → 400；正常 items → 200，mock 支付全流程回归通过 |
| T5 | 管理台商品页 | admin 新导航页 | 建改删（下架）/传图/排序全流程可用；游客端刷新即时反映 |
| T6 | 游客端 API 渲染 | 商城网格动态化 | 视觉与静态版一致；筛选正常；API 失败有兜底提示；名称随语言切换 |
| T7 | cart.js 适配 | data-* 提取 | 加购/数量/总价正确；旧 localStorage 购物车做一次 id 迁移或提示清空 |
| T8 | 回归 | 冒烟清单执行 | 浏览→筛选→加购→下单→模拟支付→收播卡推荐链路全通 |

工作量预估：T1-T4 约 1 天，T5 约 0.5 天，T6-T7 约 0.5 天，T8 约 0.5 小时。

## 六、风险与边界

- **购物车兼容**：存量 localStorage 里 id=图片文件名，与新 sku 体系冲突 → 首次加载检测旧结构即整体迁移/清空（演示期选清空+提示）
- **图片迁移**：首期不搬文件，seed 沿用现有静态路径；仅新上传走 `uploads/products/`
- **多语言**：商品名/描述仅中英（现状静态卡也只有中文），其余语言回退中文——不阻塞上线
- **部署顺序**：后端先行（无消费方可先合），前端渲染改造与后端同批部署避免空窗；管理台随批
